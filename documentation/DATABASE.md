# Database Documentation

The Rental Platform uses an in-memory **H2 Database**, automatically generated by **Spring Data JPA**.
The schema is simple and optimized to support the catalog, authentication, cart, and checkout workflow.



### ***1. Database Configuration***

Defined in `application.properties`:

```
spring.application.name=rentalplatform

spring.datasource.url=jdbc:h2:mem:rentaldb
spring.datasource.driverClassName=org.h2.Driver
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.defer-datasource-initialization=true

spring.h2.console.enabled=true
spring.h2.console.path=/h2-console
```

**Purpose:**

* In-memory DB that resets on every restart (ideal for POC)
* Automatic schema creation from JPA entities
* SQL logging enabled for debugging
* Web Console available at:
  `http://localhost:8080/h2-console`
* Loads initial demo data via `data.sql`



### ***2. Tables Generated (via JPA)***

Spring JPA automatically creates the following tables based on the entity classes:



#### **users**

| Column   | Type    | Notes          |
| -------- | ------- | -------------- |
| id       | PK      | Auto-increment |
| name     | varchar | Not null       |
| email    | varchar | Unique         |
| password | varchar | BCrypt hashed  |
| role     | varchar | “USER”         |



#### **categories**

| Column      | Type    |
| ----------- | ------- |
| id          | PK      |
| name        | varchar |
| description | varchar |



#### **products**

| Column      | Type    | Notes           |
| ----------- | ------- | --------------- |
| id          | PK      |                 |
| name        | varchar |                 |
| description | varchar |                 |
| available   | boolean |                 |
| category_id | FK      | → categories.id |



#### **orders**

| Column    | Type    | Notes        |
| --------- | ------- | ------------ |
| id        | PK      |              |
| startDate | date    | Rental start |
| endDate   | date    | Rental end   |
| status    | varchar | “Confirmed”  |
| user_id   | FK      | → users.id   |



#### **order_products** (Join Table)

Represents the **Many-to-Many** relationship between Orders and Products.

| Column     | Type | Notes         |
| ---------- | ---- | ------------- |
| order_id   | FK   | → orders.id   |
| product_id | FK   | → products.id |



### ***3. Entity Relationships (ERD)***



#### **User ↔ Order**

**One-to-Many**

* One User can have multiple Orders
* Stored via `user_id` in `orders` table


#### **Category ↔ Product**

**One-to-Many**

* Each Category contains many Products
* Stored via `category_id` in `products` table



#### **Order ↔ Product**

**Many-to-Many**

* Implemented with join table `order_products`
* One order can contain multiple products
* A product can appear in many orders
